# Agent Project Memory

## Project Summary

Suspicious Login Detection API: a FastAPI service that evaluates login events and returns a risk score, decision, and reasons. The project plan is in [PLAN.md](./PLAN.md), and setup instructions will be maintained in [README.md](./README.md).

## Current Status

- **Current phase:** Complete — Phase 7: Deployment and Hardening
- **Latest tag:** `v1.0.0` (created locally; not pushed)
- **Current step:** Complete
- **Validation limitations:** Docker, Python 3.12, Gitleaks, live PostgreSQL, and a Git remote were unavailable locally; container builds, hosted workflows, and publication were not executed. GeoIP lookups require a separately obtained GeoLite2 City database.

## Folder Structure

- `app/` — FastAPI service, settings, database session, and ORM models
- `app/db/models.py` — SQLAlchemy models for stored login data
- `app/db/repositories.py` — transaction-aware data-access classes
- `app/redis_counters.py` — Redis-backed failed-attempt counters
- `app/geoip.py` — GeoLite2 IP-to-location lookup
- `app/evaluation.py` — rule context construction, scoring, and event persistence
- `app/demo.html` — local browser console for testing login evaluation
- `app/user_agent.py` — browser, OS, and device classification
- `app/features.py` — standalone login feature calculations
- `app/ip_reputation.py` — supplied IPv4/IPv6 high-risk IP and CIDR matcher
- `app/rules/` — typed rule context, abstract rule base, and rule registry
- `app/scoring.py` — capped weighted scoring and configurable decision thresholds
- `app/model_registry.py` — versioned model artifacts, validated metadata, and latest manifest
- `app/ml_inference.py` — registered Isolation Forest loading and bounded anomaly scoring
- `app/ml_data.py` — reproducible synthetic data and strict labeled CSV loading
- `app/ml_features.py` — normalized model feature schema and context conversion
- `app/ml_training.py` — normal-only Isolation Forest training
- `app/ml_evaluation.py` — labeled holdout metrics and model evaluation
- `app/metrics.py` — privacy-safe Prometheus request and decision metrics
- `app/rate_limit.py` — hashed API-key Redis fixed-window limiter
- `Dockerfile` — Python 3.12 multi-stage non-root API image
- `alembic/` — schema migration environment and revisions
- `tests/` — API and data-layer tests
- `tests/test_geoip.py` — GeoLite2 lookup unit tests using a stub reader
- `tests/test_user_agent.py` — user-agent parsing and device-class tests
- `tests/test_features.py` — travel-speed and feature-calculation tests
- `tests/test_ip_reputation.py` — high-risk IP/CIDR membership tests
- `scripts/` — maintenance and model scripts; includes `generate_synthetic_data.py`, `train.py`, and `evaluate.py`
- `docs/` — supplementary documentation
- Root — project metadata, environment template, license, plan, and setup guides

## Common Commands

From the activated project virtual environment, install the project with `python -m pip install -e ".[dev]"`, apply database migrations with `alembic upgrade head`, start the API with `uvicorn app.main:app --reload`, and run `pytest --cov=app --cov-report=term-missing --cov-fail-under=80 -q`, `ruff check .`, `mypy app`, and `pre-commit run --all-files`.

## Architecture Decision Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-11-25 | Use the stack and high-level architecture specified in `PLAN.md` (FastAPI, PostgreSQL/SQLite, Redis, scikit-learn). | This is the project plan's proposed baseline; details remain subject to the planned implementation steps. |
| 2026-11-25 | Set default decisions to `0–39 allow`, `40–78 challenge`, and `79–100 deny`. | The user chose to preserve the plan's example where a score of 78 is `challenge`; these ranges resolve the conflicting earlier defaults. |
| 2026-11-25 | Use the MIT license and `API_KEY` as the planned API-key environment variable. | The license is a permissive baseline; `API_KEY` gives the previously unnamed setting an explicit placeholder without adding a credential. |
| 2026-11-25 | Require a configured API key for login evaluation, compare keys with `compare_digest`, and keep `/health` public. | Authentication fails closed with `503` when `API_KEY` is unset, preventing an unconfigured service from accidentally accepting evaluations. |
| 2026-11-25 | Store Redis failed-attempt counters under hashed user IDs and set each fixed-window TTL atomically on its first increment. | This avoids exposing raw identifiers in Redis keys and keeps window expiry stable as additional failures arrive. |
| 2026-11-25 | Use MaxMind's `geoip2` reader with the configured GeoLite2 City database; return `None` for addresses without records and surface database/configuration errors. | Callers can distinguish an unlisted address from a broken or missing database without the lookup silently hiding operational failures. |
| 2026-11-25 | Represent rule inputs as an immutable context and evaluate named, weighted rules in registration order. | Unique names keep reason identifiers unambiguous, and deterministic order makes rule outputs stable for API responses and tests. |
| 2026-11-25 | Trigger impossible-travel risk only above 900 km/h and assign it weight 40. | The plan defines the strict speed threshold; the initial weight reaches the lowest challenge score while treating approximate GeoIP as a signal, not standalone proof for denial. |
| 2026-11-25 | Trigger brute-force risk at five consecutive failures or five distinct users from one IP; assign weight 60. | The plan requires both brute-force and credential-stuffing signals; separate context counts allow either signal to trigger the rule. |
| 2026-11-25 | Trigger the new-login rule only when both device and country are new; assign weight 30. | The plan describes the paired signals as a combination, so either signal alone remains insufficient to activate this rule. |
| 2026-11-25 | Trigger the high-risk IP rule for a positive caller-supplied reputation match and assign weight 40. | Reputation matches are only as trustworthy as the caller's maintained list, so the rule contributes challenge-level risk without denying on its own. |
| 2026-11-25 | Treat a time-of-day deviation of at least six hours as unusual and assign weight 15. | The deviation helper returns circular UTC distance; the lower weight lets time-of-day contribute without making it decisive by itself. |
| 2026-11-25 | Sum triggered rule weights with a cap at 100; classify scores using configurable 39/78 upper bounds. | These defaults preserve the agreed 0–39 allow, 40–78 challenge, and 79–100 deny behavior while keeping the score bounded. |
| 2026-11-25 | Build API rule context from persisted event/profile history; make GeoIP opt-in and configure reputation CIDRs through settings. | Local evaluation remains runnable without private external data, while enabled GeoIP and malformed config errors stay explicit. A five-minute IP window scopes credential-stuffing counts. |
| 2026-11-25 | Use the `user-agents` parser for browser/OS families and prioritize bot, tablet, mobile, then desktop device classes. | The feature output is stable and typed, while unknown user-agent strings remain representable as `Other`/`other`. |
| 2026-11-25 | Keep login enforcement outside this scoring API; `SHADOW_MODE` does not alter returned assessments. | The service returns risk recommendations but does not authenticate or block users, so enforcement remains the consuming authentication system's responsibility. |
| 2026-11-25 | Calculate travel speed using Haversine distance (mean Earth radius 6371.0088 km), timezone-aware increasing timestamps, and return no speed when coordinates are unavailable. | These rules make the result reproducible and prevent invalid timestamps or missing GeoIP data from becoming misleading velocity values. |
| 2026-11-25 | Treat a missing profile as empty history for device/country novelty; compare opaque device IDs exactly and country codes case-insensitively; missing country data is not a new-country signal. | New-account signals remain explicit without treating unavailable GeoIP as evidence of novelty. |
| 2026-11-25 | Compare login-hour profiles in UTC and calculate distance to the nearest usual hour on a circular 24-hour clock. | The profile schema has no timezone field, so UTC provides a consistent basis for both observed login hours and feature evaluation. |
| 2026-11-25 | Store rolling failure events in hashed Redis sorted sets, use inclusive 1/5/60-minute score windows, and expire the set after one hour. | Sorted sets preserve event timestamps for genuine rolling counts, unlike the existing fixed-window counter; Lua keeps writes and multi-window reads atomic. |
| 2026-11-25 | Make IP reputation matching accept a caller-supplied IPv4/IPv6 address/CIDR list and ship no reputation feed. | No trusted VPN/Tor/proxy source or update policy is specified, so the matcher stays reusable without embedding stale or unverified classifications. |
| 2026-11-25 | Train Isolation Forest on only labeled normal rows, using seed 42 and 100 estimators; the initial 5% contamination default was superseded by the 2% default decision in step 5.6. | Isolation Forest is unsupervised; suspicious labels remain available for evaluation, while deterministic defaults make local retraining repeatable. |
| 2026-11-25 | Keep synthetic normal examples below every configured rule threshold, and ensure the distinct-user count includes at least the current user. | This keeps synthetic labels aligned with rule behavior and mirrors the API's observed per-IP count semantics. |
| 2026-11-25 | Store each trained model as an immutable versioned artifact with versioned metadata and update a stable JSON manifest last. | Consumers can resolve the current version through `MODEL_PATH` without overwriting prior model files; writing the manifest last avoids advertising incomplete artifacts. |
| 2026-11-25 | Map Isolation Forest decision margins to a bounded 0–100 anomaly score using a logistic transform calibrated to the median normal training margin. | A decision margin of zero maps to 50, while the median training-normal margin maps to 5; the output is a risk score, not a probability. |
| 2026-11-25 | Keep ML scoring opt-in with `ML_ENABLED=false` by default and blend scores at 60% rules / 40% ML when enabled. | Existing API behavior remains unchanged until operators train a model and explicitly enable inference; missing enabled models fail explicitly. |
| 2026-11-25 | Set the Isolation Forest contamination default to 2% and report false-positive rate alongside planned evaluation metrics. | On the deterministic 500-normal/100-suspicious synthetic holdout, seed 42 training produced 1.4% false positives; this is a synthetic-only check, not a real-world performance claim. |
| 2026-11-25 | Persist public event IDs and accept one feedback label (`real_attack` or `false_positive`) per event. | The API returns the same ID used to locate the stored login event; duplicate feedback returns `409`, while historical events without IDs remain readable but cannot be labeled. |
| 2026-11-25 | Update login profiles only for successful allow decisions without model anomalies or risk reasons other than the low-weight new-device-and-country signal. | This lets confirmed low-risk logins enrich the baseline without learning from failed, challenged, or otherwise flagged attempts. |
| 2026-11-25 | Expose public Prometheus metrics with route-template HTTP labels and bounded decision labels; use route templates in request logs too. | Aggregated observability remains available without exposing dynamic user IDs or creating high-cardinality labels. |
| 2026-11-25 | Make API-key fixed-window rate limiting opt-in and Redis-backed; hash API keys in Redis identifiers and fail closed on backend errors. | `RATE_LIMIT_ENABLED=false` preserves local operation without Redis; enabled limits are shared across API instances and return `429` with `Retry-After`. |
| 2026-11-25 | Build the container from Python 3.12 slim stages, run as UID 10001, and keep the default SQLite database under `/app/data`. | The runtime contains only application dependencies and writable data/model directories; health checks use the public `/health` endpoint. |
